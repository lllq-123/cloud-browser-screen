## 这份教程是什么

- **服务器那半**（`server/browser_screen.py`）是我们家 2026 年 10 月下旬做好、一直在用的虚拟屏幕后端，原件拷过来、去掉了家里的路径和名字。
- **手机那半**（`web/`）是为这份教程新写的网页，照我们家 App 里那一版移植：样式是新的，用法一样（两处例外见最后一节）。
- `server/app.py` 是给教程新写的启动器。

它不是一份在别的机器上验证过的通用安装指南。

### 照文档从零装一遍

请一个 AI 扮演「群友家的小机」，手里只有这个仓库，在一个干净的目录里照 README 和第 1、2 步装了一遍：装依赖（从 PyPI 新装，版本照 `requirements.txt`）、生成口令、起服务、本机自查 401 / 200、接 nginx、经 nginx 再验 200 / 401 / 200，全部对得上。它卡住和看不懂的地方，文档都改了（比如浏览器端口不是 9222 怎么改、怎么看端口有没有被占、linger 开没开、换口令不动别的设置）。

这一遍是在我们自己的服务器上模拟的：浏览器是一次性的，没跑 `sudo`，后台服务用临时服务代替，nginx 用的是没有 HTTPS 的临时配置。

### 宝塔面板那种 nginx

照宝塔面板默认给网站加的两条缓存规则（图片、js、css），起了一个临时 nginx 实测：`location /vscreen/` 不加 `^~`，手机网页的 js 和 css 是 404；加了，都是 200。所以仓库里那段带着 `^~`。网址少打最后的 `/`，nginx 会自己跳到带 `/` 的地址。没在真的宝塔面板上试过。

### 技术复核

Chatty（我们家另一个 AI）逐行核了服务器那半跟原件的差别、启动器和手机网页的几道安全门，重跑了仓库里的 53 项测试，全过。照他的意见改了：nginx 的备份要放到 nginx 不读的目录（他实测放在 `sites-enabled/` 旁边会让 `nginx -t` 报错）；挑网站要守「页面都是自己人管的、只走 HTTPS」两条，第 2 步加了一条用 HTTP 打开的检查；自查时口令改从管道交给 curl；还有几处说过头的话。

## 跟我们家的原件比，改了哪些

### 服务器那半（`server/browser_screen.py`）

跟我们家在用的那份逐行对过，差别只有五类：

1. 接口路径：我们家的写死在一个私有路径下；这里默认 `/vscreen/api`，由 `configure()` 传进来
2. 浏览器调试端口：我们家的写死 `127.0.0.1:9222`；这里由 `configure()` 传进来（默认还是它）
3. 日志名：改成 `vscreen`
4. 注释：去掉了家里人的名字和日期
5. 口令的变量名，和 `configure()` 的参数（多了接口路径、调试端口两个）

另外，写这份教程的时候测出来：浏览器给的网页标题是转义过的（`Tom &amp; Jerry`），手机上会显示成 `&amp;`。两边同一天加了同一行修正，所以这一处现在不算差别。

### 手机那半（`web/`）

我们家 App 里那一版是 React 写的，这里移植成不用打包的原生 JavaScript。六条行为规矩跟我们家的一样，每条都有测试守着（仓库里带的测试，或者测试场那 15 项）：

1. 回列表就断开连接，服务器才会把网页还回去
2. 换网页的时候，丢掉旧网页还在路上的帧
3. 被别处顶掉不自动重连；每 10 秒一次心跳
4. 发给服务器的是帧图上的整数像素坐标
5. 横过来看只转里面那一层，外面那层不动
6. 服务器只收白名单里的操作

两处跟我们家的不一样：

1. **不能左右划换网页**，换网页回列表点。少一种手势，就少一处跟滚动、放大打架的地方。
2. **只开着一个网页的时候，也先停在列表**，不直接进画面。我们家 App 外面还有首页可以退；教程版外面没有，直接进的话，按返回会在列表和画面之间来回弹。

### 新加的

- `server/app.py`：启动器。口令要 32～256 个可见字符；调试端口只认本机地址；只听 127.0.0.1；给网页响应加上安全相关的头（内容安全策略等）。
- 「带口令的链接」（`#token=`）：我们家 App 用不上，是给教程版新加的。
