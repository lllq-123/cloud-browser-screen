# 常见问题

按「你看到什么」找。标「实测」的，是我们家或者测试时真撞过、真验过的；标「推断」的，是按原理推的，我们没撞上过；没标的，是照着代码写的提示，或者 nginx、systemd 这类通用的排查办法。

## 装的时候（小机看这一节）

| 看到什么 | 先查什么 |
|---|---|
| `python3 -m venv` 报错，里面提到 `ensurepip` | 系统少 `python3-venv` 这个包，见[第 1 步](1-install.md)第 2 节 |
| 服务起不来，日志说 `VSCREEN_TOKEN 没设、太短或带了空格` | 设置文件没读到，或者口令不合格。照第 1 步第 3 节那段命令生成的一定合格；`ls -l ~/.config/vscreen/vscreen.env` 看文件在不在 |
| 日志说 `VSCREEN_CDP 要写成 127.0.0.1:端口` | 调试端口只能写本机地址（`127.0.0.1:端口` 或 `localhost:端口`）。这是故意的：那个端口能控制整个浏览器 |
| 日志里有 `address already in use` | 端口被别的程序占了，换一个（第 1 步第 3 节） |
| 日志里有 `unexpected keyword argument 'proxy'` | websockets 版本太老（推断：这个参数是新版才有的）。照 `requirements.txt` 在虚拟环境里重装，别用系统自带的 Python 包 |
| `systemctl --user` 报错，里面有 `Failed to connect` 和 `bus` | 先 `export XDG_RUNTIME_DIR=/run/user/$(id -u)` 再试 |
| 退出 SSH 以后服务就停了 | 没开 linger（第 1 步第 4 节） |
| 自检时带口令也是 `401` | 读口令那句没读到；或者换过口令、没重启服务 |
| 自检时 `503`，带着 `browser_unavailable` | 服务好着，连不上浏览器：浏览器没开，或者 `VSCREEN_CDP` 的端口不对（第 1 步第 0 节） |

## 接 nginx 的时候

| 看到什么 | 先查什么 |
|---|---|
| `nginx -t` 报错 | 先别 reload。按它说的行号改；改不对就用备份恢复（第 2 步第 3 节） |
| 一做备份，`nginx -t` 就报 `duplicate default server`（实测），或者警告 `conflicting server name`（推断） | 备份放在了 nginx 会读的目录里（比如 `sites-enabled/`），被当成了另一个网站。挪到 `/root/nginx-backup/` 这种地方 |
| 「用 HTTP 打开」那条是 `200` | 用 HTTP 也能打开虚拟屏幕，口令会走明文。把 location 挪到只听 443 的 `server` 里，或者让 80 端口整个跳到 HTTPS（第 2 步第 4 节） |
| 进门页 `404` | location 贴进了只听 80 端口的那个 `server`，或者没 reload |
| `502` | 虚拟屏幕服务没在跑，或者端口对不上 |
| 进门页 `200`，手机上却是一张白页、或者没有样式 | `location` 后面少了 `^~`，手机网页的 js 和 css 被站点别的规则接走了（实测：宝塔面板默认的两条缓存规则就会这样）。见[第 2 步](2-nginx.md)第 2 节 |
| 进门页 `200`，画面却一直「连接中」 | 少了 `Upgrade` / `Connection` 那两行，画面走的 WebSocket 没转过去。域名套了 CDN 的，CDN 那边也要允许 WebSocket（推断：我们家没用 CDN） |

## 手机上

| 看到什么 | 先查什么 |
|---|---|
| 进门页一直「口令不对」 | 复制的口令中间多了空格、或者少了字（头尾的空格网页会自己去掉）；或者小机换过口令。请小机重新发一次链接 |
| 进门页「连不上服务器」 | 手机没网，或者服务器上的服务没在跑（小机查：`systemctl --user status vscreen.service`） |
| 列表是空的，可小机明明开着网页 | ① 小机的网页是不是开在另一个浏览器里——虚拟屏幕只看调试端口连着的那一个；② `VSCREEN_CDP` 的端口对不对；③ 空白页、`chrome://` 开头的页、插件页本来就不显示 |
| 列表上一直是「服务器上的浏览器暂时连不上，正在重试…」 | 小机的浏览器没开，或者调试端口不对。小机用第 1 步第 0 节那条 `curl` 查 |
| 画面一直「连接中」，列表却正常 | 见上面 nginx 那一节最后一条 |
| 画面停住不动 | ① 网页刚跳到另一个网站：浏览器会悄悄停掉画面，服务器发现后会自己重新接上，稍等一下（实测）；② 看顶上的状态，是「重连中」就是网不好；③ 网页本身没在动——不动的网页大约 2 秒才来一帧 |
| 画面是黑的、白的或者空的，状态却是「已连上」 | 网页本身还没加载出来，或者就是空白页。回列表看看它的缩略图是不是也是空的 |
| 点了没反应 | ① 状态还不是「已连上」；② 点的地方网页本来就没反应，放大了再点；③ 网页上盖着一层弹窗 |
| 点不准，总偏一点 | 先放大再点（实测：放大到 3.8 倍，点 32×28 像素的小按钮，只偏了 1 像素）。我们只测过 Chromium 系的浏览器，iPhone 的 Safari 没测过 |
| 打的字没进网页 | 先在画面上点一下网页里的输入框，让光标进去，再打字 |
| 想拖滑块或图片，整幅画面却跟着走 | 按住网页里要拖的地方，停约半秒再移动。如果刚更新，请小机确认已重启 `vscreen.service`，然后刷新手机页面 |
| 放大后想继续往下翻网页 | 点画面左上角的倍数恢复原大小，再单指上下划。放大时单指划动会挪动当前画面 |
| 「发送」是灰的 | 打字栏是空的，或者画面还没「已连上」 |
| 开了「密码」，画面上看不出区别 | 正常，它只管你手机这一头（实测：落落第一次用也问了这个），见[第 3 步](3-phone.md)第 4 节 |
| 「在别的地方打开了，这里先停下」，可我没在别处开 | 同一台手机上开了两个标签页，也算两个地方（推断）。点「回列表」再进就好。**要是确定没在别处开、还一直被顶，口令可能在别人手里，马上请小机换口令**（第 2 步第 5 节） |
| 一会儿「已暂停」一会儿又接上 | 切到别的 App、锁屏就会暂停，回来自己接上。这是故意的：暂停的时候把网页还给小机 |
| 很费流量 | 一直在动的网页每秒 500 多 KB（实测），看完就点「返回」；不动的网页几乎不费 |

## 小机这边

| 看到什么 | 先查什么 |
|---|---|
| 你在看画面的时候，小机的命令变慢了 | 正常（实测：从 1 秒左右变成 6 秒左右，照样能成）。你看的那个网页被留在了最前面，看完点「返回」就恢复 |
| 登录页开着开着自己没了 | OpenCLI 的网页闲置一会儿会被自动关掉，开的时候把 `OPENCLI_BROWSER_IDLE_TIMEOUT` 调长（实测，见[第 4 步](4-login.md)） |
